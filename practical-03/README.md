# Практична робота №3 — Миколайчук Микола, П-325

## Тема проєкту: Гра Tetris

### Обґрунтування вибору методів GET / POST
Усі три форми (`login.html`, `register.html`, `create-mode.html`) використовують метод **POST**, оскільки:
1. **Login / Register**: Передають конфіденційні дані (паролі). Якщо використати GET, пароль опиниться у відкритому вигляді в URL-адресі.
2. **Create Mode**: Форма створює нову сутність (кастомний режим) у базі даних, що є прямою функцією методу POST.

*Примітка:* Реальна перевірка збігу паролів при реєстрації буде реалізована на Backend.

### Таблиця правил HTML-валідації (Предметна форма - create-mode.html)

| Поле | Тип | Обов'язкове | Обмеження | Чому |
| :--- | :--- | :--- | :--- | :--- |
| Назва режиму (`title`) | `text` | Так | 3–50 символів | Назва не може бути пустою, але й не має ламати інтерфейс довжиною. |
| Опис правил (`description`) | `textarea` | Так | Немає | Гравці мають розуміти, у чому суть цього режиму. |
| Розмір поля (`gridSize`) | `select` | Так | Тільки `<option>` | Механіка гри підтримує лише три конкретні типи сіток. |
| Початковий рівень (`startLevel`) | `number` | Так | Від 1 до 15 | Обмеження швидкості гри (на рівні 16+ гра стає неіграбельною). |
| Бонуси (`bonuses`) | `checkbox` | Ні | Декілька значень | Режим може бути як без бонусів (класика), так і з усіма одночасно. |
| Генератор фігур (`rngType`) | `radio` | Так | Одне значення з групи | Механіка випадання фігур може бути тільки однією для конкретного матчу. |

### Майбутні маршрути (Routes)
- Вхід: `POST /api/auth/login`
- Реєстрація: `POST /api/auth/register`
- Створення режиму: `POST /api/game/custom-mode`
